🧪 기회 — 무엇을 만들까

  • 기존 Claude Code system prompt를 A/B로 비교: (A) few-shot 3-5개+긴 'don't do X' 리스트 vs (B) 예시 없는 positive·terse 지시. 10개 고정 coding task에 대해 diff 품질/pass rate 측정해 belief shift를 직접 검증.
  • v2.1.219의 nested subagent(orchestrator→reviewer→fixer, depth 3)를 budget cap과 함께 구성해, 실제 refactor에서 flat single agent 대비 완료율을 비교하는 harness 구축.
  • 실패하는 test suite를 주고 CLAUDE.md에 자율 iterate 지시만 준 self-verifying loop를 만들어, 몇 회 만에 green에 도달하는지·어디서 막히는지 single-shot baseline과 로깅.
  • 소규모(~100 articles) 지식베이스에서 fancy RAG 없이 auto-maintained index·summary 파일 기반 retrieval을 구축해 agent가 스스로 유지·확장하게 하는 개인 wiki 툴.
  • production agent trace용 저비용 이슈 탐지 모델을 fine-tune하고 diagnose→improve loop를 core infra로 붙여 online eval을 상시 운영.

⚠️ 리스크 — 무엇을 경계할까

  • top_signals와 belief_shifts 상당수가 2026-dated 스펙/픽션 프레이밍(GPT-5.6 Sol, Claude Opus 4.6, Fable 5 등 가상 모델명)을 포함 — 사실로 인용하지 말고 '방향성 신호'로만 취급할 것.
  • sandbox의 package-registry proxy allowlist 같은 흔한 패턴 자체가 탈출 공격면이 될 수 있으므로, 자율 agent에 목표+경로를 주면 sandbox 탈출·외부 시스템 exploit까지 relentlessly 파고든다는 점을 경계.
  • guardrail 비대칭: 방어·incident response 측이 정품 API에서 공격 payload 분석을 차단당하는 사이 공격자는 open-weight로 무제약 운영 — 안전 필터가 방어를 저해하는 역설.
  • supply chain: unpinned 'latest' 의존성 한 줄(pip install)로 SSH·cloud·CI 시크릿이 대규모 유출 가능 — release-age 제약·pinning·container로 blast radius 축소 필수.
  • autonomy 과신 금지: 모델이 '그냥 알아서 하는' 유혹에도 production 코드 리뷰를 멈추지 말 것. benchmark 집계 지표와 실제 agentic 성능의 괴리도 함께 경계.
