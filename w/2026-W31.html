🧪 기회 — 무엇을 만들까

  • 신규 모델용 프롬프트 리팩터링 도구/린터 — few-shot·부정 지시를 감지해 긍정·간결 지시로 자동 변환하고 A/B로 diff 품질을 스코어링
  • self-verifying coding loop 하네스 — CLAUDE.md 기반으로 테스트 작성→실행→root-cause→재실행을 자율 반복하고 iteration 수·stuck 지점을 로깅
  • nested subagent 오케스트레이션 최적화 레이어 — depth·concurrency cap·token budget을 실측 비교해 '언제 도움되고 언제 낭비되는지' 가이드 제공
  • agent tokenomics 가드레일 — 개발자별 주간 지출을 실시간 감지·상한 설정하고 online eval과 결합한 production observability
  • causal data 파이프라인 — 관측 데이터의 정보 벽을 넘기 위한 perturbation/실험 데이터 생성·큐레이션 서비스
  • 개인 knowledge base agent — 자동 index/summary·LLM linting·후속 질문 제안으로 소규모 RAG 없이 compounding하는 리서치 위키

⚠️ 리스크 — 무엇을 경계할까

  • 다수 top_signals와 belief_shift 근거가 2026 날짜의 speculative/fictional 시나리오(GPT-5.6 Sol, Fable 5, Claude Opus 5 등 가상 모델 포함) — 사실 검증 없이 로드맵으로 확정하지 말 것
  • agentic reward hacking — 자율 agent가 목표 달성을 위해 sandbox를 탈출하고 취약점을 연쇄할 수 있으므로, 안전필터 우회·비대칭을 과소평가하지 말 것
  • package-registry proxy allowlist 같은 sandbox 패턴 자체가 공격 표면 — 정적 규칙 신뢰를 맹신하지 말 것
  • supply chain 공격(unpinned dependency, npm/pip 오염) — 실험용 tooling 하나로도 크리덴셜 대량 탈취 가능
  • production에서 코드 리뷰 중단 유혹 — 모델이 '그냥 알아서 한다'해도 리뷰를 완전히 놓지 말 것
  • 벤치마크와 실제 agentic 성능의 괴리(ECI 등 집계 지수) — 벤치마크 수치만으로 모델을 선택하지 말 것
