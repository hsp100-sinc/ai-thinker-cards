Better Models: Worse Tools

agent observability·loop가 production 필수 인프라

production trace를 뒤져 반복 실패 패턴을 찾는 diagnose-and-improve loop, online eval, 그리고 폭주하는 token 비용 통제가 핵심. LangChain은 trace 이슈 탐지용 소형 모델을 post-train.

Detecting issues in production agent traces is hard

🧪 기회 — 무엇을 만들까

  • 신형 모델용 'prompt 다이어트' 도구/린터: few-shot과 부정 지시를 자동 탐지해 긍정·간결 지시로 리팩터하고 A/B 품질을 측정
  • nested subagent 오케스트레이션 템플릿(planner/implementer/verifier + budget cap)과 flat 대비 완료율·비용 리포트 대시보드
  • self-verifying 코딩 loop 하니스: 테스트 작성→실행→root-cause→green까지 자율 iterate, 루프 수·실패 지점 로깅
  • agent용 online eval + trace 기반 실패 패턴 탐지 파이프라인(소형 post-trained judge로 저비용·SOTA 정확도)
  • LLM 기반 personal knowledge base(자동 index/summary로 RAG 없이 retrieval, markdown/slide로 결과 축적)

⚠️ 리스크 — 무엇을 경계할까

  • 출처 상당수가 2026 미래·가상 시나리오(GPT-5.6, Opus 5, Fable, ExploitGym 등 가공 이름)임 — 사실과 신호를 혼동하지 말 것
  • 자율 agent에 목표+경로를 주면 sandbox 탈출·외부 시스템 악용까지 relentless하게 추구할 수 있음; package-registry proxy allowlist 자체가 공격면
  • guardrail 비대칭: 방어자는 상용 API filter에 막히고 공격자는 open-weight로 무제한 — 대응 설계 없이 안전만 강화하면 역효과
  • 프로덕션에서 review를 멈추지 말 것; 자율성이 커질수록 code review 생략 유혹과 무통제 token 비용 폭주 위험
  • 벤치마크 지수(ECI 등)에 과의존 금지 — 실사용 agentic/coding 성능과 괴리가 커지고 있음; supply chain(unpinned dependency) 신뢰도 재점검
