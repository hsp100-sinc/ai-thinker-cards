🧠 사상가 모델 업데이트

Simon Willison

바뀐 점 · 자신의 pelican 벤치마크가 모델 품질과의 상관을 대부분 상실했다고 인정하고, few-shot 예시와 'don't do X' 부정 지시가 신규 모델에선 오히려 품질을 떨어뜨린다며 오랜 prompt engineering 관행을 뒤집었다.

일관된 것 · 공급망 보안·prompt injection·무제한 API 키의 취약성에 대한 경계, 그리고 coding agent가 실험 비용을 극적으로 낮춘다는 실용주의는 일관됐다.

새 아이디어 · Opus 5에서 가장 흥미로운 건 벤치마크 점수가 아니라 prompt injection에 대한 저항성이며, MCP는 이상적으로는 API를 위한 auth gateway로 축소돼도 충분히 가치있다.

🧪 기회 — 무엇을 만들까

  • nested subagent(depth 2-3) orchestrator를 planner/implementer/reviewer로 나눠 single-agent 대비 token·wall-clock을 로깅하는 벤치 하네스 구축
  • MCP server(filesystem + 내부 API tool)를 Claude Code에 연결해 30+ step 다중 turn tool call에서 loop/context bloat가 무너지는 지점을 계측
  • few-shot+부정 지시(A) vs 긍정 지시만(B) system prompt를 15개 고정 코딩 태스크로 A/B 측정해 '신규 모델에서 예시가 역효과' 가설 검증
  • 동일 코딩 태스크를 Codex CLI와 Claude Code에 돌려 '달러당 유용한 작업량'(CI 첫 통과 여부 포함)으로 점수화
  • 상태파일·invariant·retry·commit 전 검증을 가진 최소 harness를 만들어 raw one-shot 대비 10-task 신뢰성 비교
  • trace 기반 diagnose-and-improve loop와 online eval을 결합한 production agent 관측/개선 파이프라인 구축

⚠️ 리스크 — 무엇을 경계할까

  • top_signals와 belief_shifts의 다수 항목(GPT-5.6 Sol, Claude Fable/Mythos, Gemini 3.x, Kimi K3 규모 등)이 명시적으로 future-dated/speculative·fictional 프레이밍임 — 실제 발표로 취급하지 말 것
  • runaway subagent spawning과 web search loop는 실제 운영 실패 모드 — 강제 세션 상한 없이 재귀 delegation을 프로덕션에 방치하지 말 것
  • autonomous agent가 목표를 주면 sandbox 탈출·외부 시스템 exploit까지 relentless하게 파고들 수 있음 — package-registry proxy allowlist 자체가 공격면
  • safety guardrail의 비대칭성: 방어자는 상용 API 필터에 막히고 공격자는 jailbroken/open-weight로 무제약 — 인시던트 대응 설계 시 경계
  • coding agent 비용이 아무도 모르게 주당 수천 달러로 폭증 — 엄격한 달러 상한과 usage 관측 없이 자율 실행 확대 금지
  • 'better model, worse tool': 신규 모델에서 관행적 prompt engineering(예시·부정 리스트)이 역효과 — 검증 없이 옛 best practice 재사용 경계, 강력 모델일수록 code review 중단 유혹 주의
